# 小游戏人物形象修复与重做说明

## 结论

**人物为什么之前是黑的（根因）**

1. 移植后的角色代码与 legacy 桌面版**逐字节相同**（`diff legacy/desktop/src/render/character.ts minigame/src/render/character.ts` 无差异），场景/球场文件也相同——不是贴图丢失、不是模型被替换成占位几何体。
2. 在浏览器和 wx 垫片模拟页里渲染完全正常（见修复前截图），说明问题只出现在**微信小游戏真实 WebGL 运行时**（开发者工具/真机）。
3. 全场景里**只有角色**使用了「BackSide 放大描边壳」技术：给身体和头部各套一个放大 4.5%~5% 的反向壳，颜色是接近纯黑的深青 `#1d2b3d`（`OUTLINE_COLOR`）。球场、球网、排球都没有这种壳——这与"只有人物变黑、场景正常"的现象完全吻合。
4. 描边壳只比本体表面外扩约 1.4cm，而相机参数是 `near=0.1 / far=260`。移动设备（尤其微信小游戏在部分 Android 机型）的 WebGL 深度缓冲只有 16 位，在这个视距比下，20 米外（比赛机位到角色的典型距离）的深度量化精度约 6cm——描边壳与本体深度值相同，深度测试随机/恒胜，**深色描边壳糊满整个角色表面 → 人物看起来纯黑**。桌面浏览器是 24 位深度缓冲（精度 0.24mm），所以同一包在 PC 上正常。

一句话：**不是素材问题，是描边壳 + 低精度深度缓冲的渲染事故。**

**现在改成什么样**

按「低多边形卡通」方向重做（不依赖外部美术素材），同时从机制上根除黑块：

- **移除全部 BackSide 描边壳**（根因修复）；相机 `near/far` 收紧为 `0.5/160`，深度精度提升约 8 倍，杜绝同类深度冲突。
- **三重保险防黑**：五官（眼白/瞳孔/高光/眉毛/嘴/腮红）全部改用无光照 `MeshBasicMaterial`，任何光照异常下都清晰可读；受光材质统一加微量自发光（`emissiveIntensity 0.22`），光照再弱也不会糊成黑块。
- **造型**：大头小身 Q 版比例保留并强化（头身比更大、加了耳朵），4 种发型（蘑菇头 / 侧分头带 / 马尾 / 双丸子呆毛）× 6 发色 × 4 肤色随机组合。
- **辨识度**：球衣号码改为白底圆牌 + 队色描边，**背后大牌 + 胸前小牌**，正反两面都能认出队伍；新增领口白边、胸前白横条纹。
- **两队配色**：我方草绿系（`#22c55e` 族）、对手珊瑚红系（`#ff5d73` 族），明度色相差距拉大，竖屏小屏一眼区分；脚下光环、名牌胶囊延续队色。

## 关键改动

| 文件 | 改动 |
|---|---|
| `minigame/src/render/character.ts` | 整体重写：去描边壳、新脸型/号码牌/条纹/领口、无光照五官、自发光保险、双队新配色；动作逻辑（跑动/跳跃/扣球/拦网/扑救/眩晕/庆祝/眨眼）原样保留 |
| `minigame/src/render/scene.ts` | 相机 `near 0.1→0.5`、`far 260→160`（仅渲染参数，不碰玩法） |

未改动任何模拟/输入/UI/音频代码，`CharacterView` 对外 API（`root` / `label` / `celebrate()` / `dispose()` / `update()`）保持不变。

## 遗留问题

- 微信开发者工具/真机环境本机无法启动验证，建议在微信开发者工具里跑一遍确认真机表现；若个别机型仍有异常，方向是进一步检查 `wx.createOffscreenCanvas` 的 2D 画布作为 `CanvasTexture` 上传（名牌/号码贴图）的兼容性。
- 角色面部细节主要在面向镜头时可见；当前比赛机位以背影/侧影为主，这是玩法视角决定的，与 legacy 一致。
