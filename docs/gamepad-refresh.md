# 小游戏底部手柄区优化说明

## 结论与设计思路

**现状怎么画的**：手柄不是 DOM/贴图资源，是 Three.js 屏幕空间正交层（[layer.ts](../minigame/src/ui/layer.ts)）里用平面圆 + canvas 文字 sprite 拼的（[gamepad.ts](../minigame/src/ui/gamepad.ts)），蓄力条/记分板在 [hud.ts](../minigame/src/ui/hud.ts)。

**"丑"的具体原因**（改动前截图 `gamepad-before.png` 可见）：

1. **按键是纯平高饱和色圆**（橙/蓝/紫/粉），无渐变、无投影、无高光、无图标，全靠白色文字区分——像调试占位 UI，且四种颜色与新卡通人物（草绿/珊瑚红体系）不协调；
2. **摇杆是大白盘 + 细灰环 + 小白旋钮**，没有中心感和外圈刻度，像占位符；
3. **手柄区背景是一块死板的浅灰蓝纯色平板**加 1px 分割线，与球场的雪地渐变、卡通人物完全割裂；
4. **蓄力条是 8px 高的直角白底细条**，单薄廉价；
5. **按压反馈弱**：按下只是缩放 0.92 + 颜色提亮 26，几乎感知不到。

**新设计**（与卡通人物统一语言）：

- **手柄区背景**：藏青半透明渐变带（顶部 52% → 底部 88% 不透明度）+ 顶部 10px 柔和白色高光过渡——彩色按键和白色摇杆环在深色带上跳出来，但半透明不抢球场视线；
- **四键**：烘焙投影 + 上浅下深渐变 + 白描边 + 顶部高光弧的"糖果"质感；**图标 + 文字双通道**（击球=排球、跳跃=双箭头、拦网=网格栅、冲刺=风线），不再只靠文字；配色珊瑚红/天蓝/柔紫/明黄，与角色球衣同一卡通色系；主键"击球"放大到 r33，其余 r26/26/23，大小即重要度；**按下换压暗贴图 + 去高光 + 描边加实 + 缩放 0.9**，反馈明确；
- **摇杆**：半透明圆盘 + 白色外圈 + 内圈细环 + 四方向刻度点（明确中心与外圈），旋钮是我方主色绿的渐变球（白描边 + 高光点），拖出时旋钮放大 8%、底盘放大 4%，有"握感"；
- **蓄力条**：圆角深色轨道（与手柄带同一藏青）+ 绿→黄→红渐变填充，加高到 14px，与按键/角色配色呼应；
- 记分板/播报/触球计数本来就是白色胶囊体系，与深色带协调，未动。

## 关键改动

| 文件 | 改动 |
|---|---|
| [gamepad.ts](../minigame/src/ui/gamepad.ts) | 视觉层重写：背景改渐变贴图 sprite；摇杆底盘/旋钮改 canvas 烘焙贴图；四键改 canvas 烘焙贴图（常态/按压两张常驻复用，直接换 `map`，不走会 dispose 的 `setSpriteTexture`）；触控命中、多点触控、蓄力松手逻辑**一行未动** |
| [hud.ts](../minigame/src/ui/hud.ts) | 蓄力条轨道/填充改圆角贴图 + 渐变，位置与显隐逻辑不变 |

所有贴图在构造时一次性烘焙（2x 分辨率保清晰），运行时零 canvas 重绘，性能无回退。

## 遗留问题

- 刘海屏安全区沿用原有 `safeBottom` 上限 30px 的钳制，布局逻辑未变；真机若有更大安全区可再放开上限；
- 微信开发者工具/真机未实测，建议跑一遍确认深色带透明度在实机上的观感；
- 按键图标为手绘简笔风格，若后续要更精致的图标可替换 `buttonTexture` 里的 icon 绘制函数，结构已预留。
