# AI 队友配合与得分难度（v0.1.0 人机对局）

本次只改人机对局的 AI 行为、扣球判定窗口与难度参数；联机协议、UI 布局、清晰度、启动兜底均未改动。

## 1. 「跳跃 + 击球」到底是不是扣球？

**是扣球，但改动前的窗口只有约 0.1~0.2 秒，真人基本按不出来。**

扣球不是单独的按键，而是击球命中瞬间按状态判定的（[world.ts](../minigame/src/sim/world.ts)）：

- 改动前判 `kind = 'attack'` 的硬条件：
  - 必须**离地**（`!p.grounded`）；
  - 球心必须**高于胸口 1.5 米**（`ball.pos.y > p.pos.y + 1.5`）；
  - 同时还要过常规触球判定 `ballInReach`：胸口到球心 3D 距离 ≤ 1.4 + 球半径 0.2 = 1.6 米；
  - 受每队 3 次触球上限、`hitCd 0.28s`、全局 `hitGap 0.1s` 约束。
- 跳跃：`jumpVelocity 8` / `gravity 22` → 顶点 1.45m（0.36s），滞空 0.73s；跳跃键是**按下边沿**，击球键可按住（0.35s 输入缓冲，按住会持续尝试）。
- 把两个条件叠起来算：起跳顶点胸口高 2.45m，球必须 > 3.95m 且 3D 距离 ≤1.6m，球越高允许的水平距离越小 → **有效判定窗口约 0.12~0.18s**，还要球刚好在那个时刻落在头顶。真人在竖屏 3D 视角里几乎无法稳定命中。

改动后的扣球判定 `attackWindow()`：

| 条件 | 旧 | 新 |
| --- | --- | --- |
| 触球次数 | 不限（第一、二拍跳打也算） | **必须是第三拍**（`touches >= 2`） |
| 是否空中 | 必须离地 | 必须离地 |
| 与球的水平距离 | 隐含在 3D 1.6m 内 | ≤ `spikeReachXZ = 1.45m` |
| 球相对胸口高度 | > 1.5m | **0.7 ~ 2.2m** |
| 是否在己方半场 | 是 | 是 |
| 同一人连击 | 只降力量 | 不允许连续两次扣球 |
| 有效窗口 | ≈0.12~0.18s | **≈0.4~0.5s** |

结论：**跳跃 + 击球就是扣球**；改动后只要玩家在第三拍、在己方半场、球在头顶 0.7~2.2m 且水平 1.45m 内，跳起来按击球就能打出来，窗口从 0.1 秒级放宽到 0.4 秒级。

## 2. 改动前的 AI 决策链

`AIBrain.think()` 每 tick 产出一份与真人完全相同的 `ControlInput`，只按 `world.touches` 分档：

- **touches = 0（第一拍）**：离落点最近的人接一传，另一人向网前靠。
- **touches = 1（第二拍）**：由 `attackPlan.setterId` 去接球并「二传」；主攻去进攻区。
- **touches = 2（第三拍）**：`attackPlan.attackerId` 追球起跳扣杀；球掉太低则低手过网。
- 一传时 `attackPlan` 由接球人决定：单人模式固定真人当主攻 → 一传者（人机自己）当二传。

问题出在三个地方：

1. **一传 → 二传 → 扣球全落在同一个人机身上**。旧代码里 AI 接一传后给自己二传、自己扣（`AI 自己连打三拍`），真人拿不到球；
2. **AI 扣球起跳按「球现在多高」判断**，不看球什么时候下落到扣球高度，起跳时机经常错；
3. **AI 接扣球没有反应延迟/覆盖范围限制**，普通与困难档几乎不漏球，回合被无限拉长。

根因对应关系：

- **玩家扣杀成功率 3.8%~5.4%**：窗口只有 0.1~0.2s（见第 1 节），且第一、二拍跳打不算扣球的旧规则让「跳起来打」经常变成普通垫球；
- **平均回合 32~47 次触球、30~43 秒**：AI 接扣球没有延迟/覆盖限制，几乎每球都能防起，回合成了一条不断循环的「扣—防—扣」；
- **AI 连打三拍 6.7~7.8 次/场**：一传者同时被指定成二传和主攻，AI 自己吃掉了三次触球，玩家没有参与机会（简单档队友传玩家 0 次）；
- **玩家得分几乎全部来自扣球**：对手防守成功率高，玩家靠吊球/对方失误拿分很难。

## 4. 新的 AI 队友配合规则

### 4.1 触球分工（每队最多 3 拍）

`World.attackPlan[team] = { setterId, attackerId }` 在第一拍确定，之后按拍更新：

| 拍数 | 规则 |
| --- | --- |
| 第一拍 | 最近的人接一传。`preferredAttacker()` 决定谁是本轮主攻：<br>• 真人离进攻区 ≤3.8m 或**没有移动** → 真人主攻、人机二传（AI 做球给玩家扣）；<br>• 真人站在深位且正在移动 → 人机主攻、真人做二传（**玩家传球 → AI 扣杀**）。 |
| 第二拍 | `setterId` 负责二传（`kind='set'`，高点吊到 `attackZone`，落点 z=±1.75m）；主攻提前跑到进攻区。若二传发现真人主攻根本赶不上（离进攻区 >3.6m 且没在动），才改成 `kind='send'` 直接推过网，避免吊给空气。 |
| 第三拍 | 只有 `attackerId` 可以扣（`attackWindow` + `attackAim`）；球掉太低则低手处理过网；队友兜底只在球低于 1.5m 且距离 <1m 时才碰。 |

- 第二拍谁传谁就当二传（`t===1 && kind==='set'` 会把 `attackerId` 改成搭档）→ 玩家在第二拍碰到球时，人机会自动变成主攻并起跳。
- 连续两次触球由 `attackWindow` 的 `lastHitterByTeam` 检查拦住；第三次触球后 `ballInReach` 直接返回 false，不会超次数。
- 批量模拟中 `AI 连打三拍` 已从 6.7~7.8 次/场降到 **0**。

### 4.2 起跳与扣球

- 起跳时机改为**预判球下落到扣球高度的时间**：`ballTimeToHeight(pos.y + chest + 1.15)` 距今 ≤ `jumpLead (±jumpErr)` 才起跳，不再「球高就跳」。
- 扣球落点按「两名防守人最近距离最大」的 7 个 x 档选点，再叠加 `attackAimError`，所以 AI 会主动打空档，不是随机乱打。
- 扣球球速由 `attackScale` 控制（`T = clamp(dist/18, 0.38, 0.65) / attackScale`），这是难度曲线的关键旋钮。

### 4.3 防守（不是「漏球」，是物理化反应）

- `Ball.lastKind` 跨过网保留，AI 能判断「对面这球是扣球」。
- `digDelay`：对面扣球后这段时间内不更新移动目标（反应不及，球速快时尤其明显）。
- `digReach`：接扣球时允许的横向离球距离，超过就救不起（扣球快 → 实际可救范围更小）。
- `blockChance` + 网前提前上步 + 起跳拦网：困难档对手会提前站到 `z=±1.25` 并起跳封堵（本期拦网碰撞事件几乎不触发，见「遗留风险」）。

改动要点与理由：

- **简单档**：对手原来完全不会扣球（`canSpike=false`），现在会给低威胁扣球（spikeChance 0.5、球速 1.0、落点误差 0.8m），接扣球范围只有 1.0m、反应 0.4s，所以看起来在打球但基本防不住；队友移动与传球误差都小，保证球能舒服送到玩家头顶。
- **普通档**：对手扣球球速 1.29（比真人快 29%），但接扣球范围 1.45m、延迟 0.13s，玩家扣杀能打穿一半左右。
- **困难档**：对手球速 1.31、落点误差只有 0.3m、接扣球范围 1.55m、延迟 0.09s，进攻与防守都明显更强；队友反而把接扣球范围提到 1.45m，保证「陪玩」成立，不会一传就崩。
- 困难档 `attackScale` 从 1.35 降到 1.31 是这次「打不动」的主要修复点：球速跨过了防守人「能否在飞行时间内跑到落点」的临界点，难度呈指数级跳变（1.30 → 58% 胜率、1.32 → 8% 胜率）。中间实验里 1.35 时玩家扣杀成功率 15.8%、被防起 84.2%；最终 1.31 时成功率 19.6%、被防起 80.4%，配合对手回球落点变差，玩家得分率从 29% 提到 43%。

## 8. 遗留风险

- **拦网碰撞事件几乎不触发（blocks=0）**：球的网碰撞只在「过网高度 ≤ 网高 2.05m」时判定，而多数扣球过网高度在 2.1m 以上，所以 AI 的「拦网起跳」目前主要是站位压迫与视觉表现（困难档 `aiJumps` 约 118 次/场）。若要真正拦死球，需要改球的过网碰撞模型（会把难度和联机同步一起牵动），本次未做。
- **headless 的「中等真人」是脚本**，不代表所有玩家手感；真人有蓄力、走位、瞄准差异，实际胜率会有偏移。
- **25% 胜率的困难档**靠近目标下限（30%±），并且 `attackScale` 在 1.30~1.33 之间会跨临界点（1.30→58% 胜、1.32→8% 胜），后续微调务必跑 20 局以上再定。
- **玩家当二传的链路**只在「AI 一传 + 玩家在深位且在移动」时触发；玩家站着不动时仍然让玩家当主攻，避免把球吊给不动的队友。
- 简单档的 `digReach 1.0 / digDelay 0.4` 是「反应慢、覆盖小」的物理化参数，不是让 AI 故意不动；但如果后续要更严格地「像真打球」，可以再把简单档对手的扣球落点误差从 0.8 收窄到 0.6。

## 9. 真人实测反馈修正

真人上手后反馈「比改动前更难玩」，且第 6 节的数据（理想机器人）与手感严重不符。这一节记录**根因、修正和拟人机器人前后数据**；第 1 节里「球相对胸口 0.7~2.2m」的扣球窗口在本节被再次修正，以本节为准。

### 9.1 现象一：AI 队友几乎不给玩家传球 —— 怀疑成立，且还有第二个断点

**根因 A：判据真的错在「是否移动」。**
改动前 `preferredAttacker()` 和 `isClosest()` 都用 `p.moving` 判断「真人是否在跑」。真人的摇杆只要在微动，`moving` 就恒为 true，于是每次一传都被判成「真人会跑动，不适合主攻」→ 全部走「真人当二传、AI 主攻」。拟人机器人（摇杆持续抖动）在改动前 16 局/档的实测：

| 难度 | 队友给玩家做球（次/场） | 玩家实际可扣机会（次/场） | 玩家扣球（次/场） |
| --- | --- | --- | --- |
| 简单 | **0.13** | 5.44 | 1.06 |
| 普通 | **0.13** | 3.06 | 0.44 |
| 困难 | **0.19** | 4.25 | 0.44 |

这就是「模拟里一场 19~21 次、真人几乎感觉不到」的来源：理想机器人站定不动，`moving=false`，因此被判定为主攻，模拟里传球次数很高；真人摇杆一直在微动，永远拿不到球。

**根因 B（顺带挖出的第二个断点）：就算传到了，真人也扣不到。**
修好判据后，第一次复测反而更差（简单档得分率 20.8%→8.2%），原因是：

1. 二传落点固定在「离网 1.75m 的进攻区」，真人常常还在跑位，球就落在身前 1~2m，只能看着落地；拟人机器人 16 局里**每场有 11.0 次「我方最后一击是队友，球落在我方半场」**（二传直接落地送分）。
2. 扣球窗口是「球心相对**胸口** 0.7~2.2m」。人一跳起来胸口升高，窗口跟着升高：球在下落而人在上升，**跳得越高反而越打不到球**。实测命中瞬间球心 2.83m、玩家跳到 y=1.40m（胸口 2.40m）→ 高度差只有 0.43m，判不成扣球，只能变成软绵绵的 `send`。
3. 设置给真人的触球容错也偏小（3D 1.6m），150~300ms 的按键延迟经常「按下去时球已经掉走」。

### 9.2 现象二：对面扣球时队友站着看 —— 怀疑成立，属于「让球逻辑 + 无救球层」

- `isClosest()` 里有一行 `if (q.isHuman && !q.moving) dq += 2.2`：只要真人站在落点附近（无论他接不接得住），AI 就把球「让」给真人；真人反应慢半拍，球就落地。
- AI 的决策顺序是「进攻准备优先」：`touches>=2` 时非主攻直接回 `z=±2.4` 的防守位；只有 `nearest > 1.5m` 才会去救，没有「来得及/来不及」的时间判断。
- 对面扣球后还有 `digDelay + reaction` 的冻结：普通档 0.16+0.15=0.31s，而扣球飞行只有 0.3~0.5s，等于**整段飞行都站着**。
- 证据（拟人机器人，普通档 16 局）：对面扣球后 1.2s 内队友平均只移动 **0.95m**；对手扣球被本方接起的比例只有 **16.1%**（87 次扣球只接起 14 次，73 次直接落地丢分）。

### 9.3 改了哪几条

| # | 位置 | 改动 |
| --- | --- | --- |
| 1 | `world.ts preferredAttacker()` | 删掉 `moving`；改为**纯位置区间**：真人离进攻区 ≤6.2m（约半个球场）就判真人主攻，否则 AI 主攻。真人默认站位离进攻区约 4.1m，稳定判成主攻 |
| 2 | `ai.ts isClosest()` | 删掉「真人不动就 +2.2m 让球」的惩罚，只看距离 |
| 3 | `ai.ts think()/updateTarget()` | 新增**救球层**：球要落在己方半场且 `<2.6s` 时先算 ETA（`落地时间 + 0.3 ≥ 跑去的时间`），够得着就先去接；**对面扣球（`lastKind==='attack' && lastHitTeam===opp`）时不再让给真人**，队友直接去救，来不及才回进攻位 |
| 4 | `ai.ts` 二传分支 | `dump`（直接把球推过网）改成只按位置：真人离进攻区 >7m 才触发；否则一律吊给真人 |
| 5 | `ai.ts` 二传瞄准 | `aimX` 从「进攻区 x」改成**主攻本人的 x** |
| 6 | `world.ts` 二传落点/弧线 | 落点从固定 `z=±1.75` 改成**主攻脚下稍靠网 0.5m**（`z = |主攻 z| - 0.5`），弧顶 6.0→4.9，让球落在人身上而不是人前面 |
| 7 | `world.ts attackWindow()` | 扣球高度判据从「相对胸口 0.45~2.4」改成**相对地面的绝对高度带 2.25~4.3m**（下沿高于网高 2.0m，避免扣到网上反弹回自家半场丢分）；水平 `spikeReachXZ 1.45→1.65`；常规触球 `reach 1.4→1.75` |
| 8 | `ai.ts shouldJump()` | 起跳时机从「球到胸口+1.15」改成「球落到扣球带下沿+0.6」，与新的绝对高度带对齐 |
| 9 | `AI_PROFILES` | 普通/困难对手球速回调（普通 1.29→**1.10**、困难 1.31→**1.22**），对手接扣球范围下调（普通 1.45→1.38、困难 1.55→1.42）；队友接扣球范围/延迟按档位重设（简单 1.15/0.12、普通 1.30/0.10、困难 1.40/0.08），保证「队友会去救」但不至于把对手扣球全接死 |

真人挡住 AI 走位的问题：`stepPlayer` 里没有玩家之间的碰撞/推挤，AI 也没有避让真人的逻辑，所以**不存在「真人物理挡住队友」**；真正的问题是上面第 2、3 条的「让球」判据，已修。

### 9.4 换了测法：拟人机器人

`tools/bench.ts --bot=human`，在原有「中等真人」之上叠加：

- 摇杆持续小幅抖动（每 90~190ms 重采样，静止时也输出微动，幅度 0.05~0.3）；
- 22% 概率间歇冲刺；
- 跳跃/击球按键统一延迟 150~300ms（模拟真人反应 + 触屏延迟），按下保持 0.14s；
- 每 6~14 秒乱按一次（0.25s 提前挥空/乱跳）；
- 击球改为「预判提前按」（游戏本身有 0.35s 输入缓冲，真人也是提前按），这样延迟后正好落在球上，避免把「延迟」误判成「必失误」。

另外修了机器人自身两个问题：发球阶段不再被按键延迟覆盖（否则永远不蓄力、每球等 9s 自动发球）；扣球机会统计改为与 `attackWindow` 同口径（必须在空中）。

## 10. 第三轮实机反馈修正（拦网物理 / 发球轮转 / 网前按钮）

### 10.1 现象一：拦网拦不到球（物理重做）

**改动前的判定链**

| 环节 | 旧实现 | 后果 |
| --- | --- | --- |
| 触发高度 | `ball.ts` 过网分支只在 `cy <= COURT.netHeight + 0.05`（2.05m）时才查拦网 | 对手扣球过网点几乎全部在 2.5m 以上，天生覆盖不到 |
| 拦网盒 | `BlockerBox` 只在 `blockHeld` 按住 / `blockCd` 期间且离地时生成 | 起跳瞬间必须与过网瞬间重合，容错接近 0 |
| 命中后 | 直接反转 `vel.z`，不区分「正面挡回」和「手边缘」 | 即使碰到也容易看起来像穿透 |

**新判定：竖直拦网面**

- 球跨越 `z=0` 的那一帧，先用 `BlockerBox` 检查拦网面：水平 `|cx - b.x| <= 0.78m`，竖直 `cy ∈ [p.y + 0.65, p.y + 2.45]`（站地时覆盖 0.65~2.45m，跳到 1.45m 高时覆盖 2.1~3.9m）。
- 竖向拦网面命中 → 球 `pos.z` 退回上一帧（不穿网），`vel.z = -vel.z * 0.55`（挡回对方半场），`vel.x *= 0.55`，`vel.y <= -1.4`（减速下坠）；手边缘命中（`|dx|/halfW > 0.8`）判「打手出界」，给横向速度并从拦网手外侧飞出。
- 拦网面没命中才走原球网判定；拦网失败完全不影响救球：`ballInReach` 与 `digs` 路径零改动，`block` 是独立世界事件。
- `lastHitTeam / lastHitterId` 归拦网方，拦到后该队重新有 3 次触球。

### 10.3 现象三：网前区域按钮语义切换

判定用「与网距离」，不用「是否移动」：

- `netMode` 在 `phase==='rally'` 且球在己方半场时：`|z| <= 2.75` 进入，`|z| > 3.25` 退出（0.5m 滞回，站在边界不会来回闪）。
- 贴图在构造时预生成 `hit/jump` 与 `spike/set` 两套纹理，`updateVisual()` 只切 `sprite.texture`，四键尺寸、命中区、糖果质感都不变。

| 按键 | 网前进攻区 | 离开后 |
| --- | --- | --- |
| 击球键 | 显示「扣杀」：`spikeEdge` → `spikeBuffer`，世界层自动起跳（球到扣球带 ≤0.62s）并在 `attackWindow` 内扣出 | 恢复「击球」+ 蓄力发球 |
| 跳跃键 | 显示「二传」：`setupEdge` → `setupBuffer`，`tryHit(force='setup')` 把球吊到进攻区，并标记 `quickAttack[队友]`，队友下一拍起跳快扣 | 恢复「跳跃」 |
| 拦网键 | 始终「拦网」 | 始终「拦网」 |
| 冲刺键 | 不变 | 不变 |

边界处理：

- 扣杀：`canAutoSpike` 不通过（触球 <2 或 ≥3、球不在己方半场、离球 >2.6m、球低于扣球带 0.4m）时清掉缓冲；此时球若在手边就退回普通击球，够不着则什么都不发生（不会误触跳跃/拦网/换人）。
- 二传：无队友或该队已触球 >1 时兜底成普通击球（`hitBuffer`），不会空按。
- 二传成功时 `quickAttack[team] = 队友 id`，队友这一拍允许在触球 1 次时直接起跳扣（快攻例外）；扣球完成后清空。

### 10.5 本节遗留风险

- **拦网数据的执行者是 AI 队友**：拟人机器人长期守后场（`humanBlockJumps = 0`/场），三档「我方拦网次数」全部由 1 号位 AI 队友贡献；真人上步拦网只有 `net-block-success.png` 一次实机证据，没有批量样本。

- **联机发球采样只覆盖对手队**：E2E 三份样本都是 `st=1`（对手两人 2→3→2）；我方 0/1 号位轮转由 bench 的 `serveBy` 数据覆盖（181:176 等）。

### 11.2 站位规则（`ai.ts coverBack` / `backCourtTarget`）

- **默认后场**：AI 队友后场基准 `|z|=4.35m`；有对方来球落点时守落点，但强制留在 `3.6~5.8m` 区间，不因追球跑到网前。
- **玩家在前排**（`|玩家 z| ≤ 3.0m`）且这一拍不是队友二传/队友主攻 → 队友必须 `coverBack`，只有这一刻它才被允许待在后场。
- **玩家后撤**（`|玩家 z| > 3.0m`）→ 解除后场约束，队友才可以上前拦网/二传；此时后场由玩家覆盖。
- **二传例外**：这一拍轮到队友做第二拍（`touches===1 && plan.setterId===队友`）才上前；**主攻例外**：这一拍轮到队友扣球时不能提前退（否则「玩家做球 → 队友快扣」会被破坏）。
- **左右分位**：后场目标 x 先按来球落点，若与玩家横向距离 `<1.5m` 则往另一侧偏 `2.2m`（限 `±3.2m`），避免同一条竖线。
- **接球优先权**：双方共用「谁更近且够得着」；AI 救球用 ETA 判定（`落点时间 + 0.42s ≥ 跑过去的时间`），够不着才回进攻位。没有「AI 站着不动」的分支。

### 11.3 自动接扣杀（`world.ts tryAutoDig`）

只在「对方攻击球」这一种情形触发，其余球（我方二传、吊球、发球）一律不自动碰：

1. `ball.lastKind === 'attack'` 且 `lastHitTeam === 对方`；球在己方半场；本队触球 <3；本人不是最近一次触球者。
2. 落点必须**界内**（`predictLanding` + `landingInBounds`）——界外球直接 return，不会「帮对手救球」。
3. 球必须在**下落**且高度带内：`y ≥ 0.35` 且 `y ≤ 2.3 / 2.15 / 2.0`（简单/普通/困难），`vel.y < 0`。球还在头顶飞向后场时不碰，避免前排截胡。
4. 水平范围按落点算：`2.15 / 1.95 / 1.75m`；**前排球员收窄到 0.55 倍**。
5. **责任区**：落点 `|z| > 3.4m` 时前排让给后排队友，除非队友已经失位（`|z| ≤ 3m` 或距离超出它的范围）。
6. **优先权**：队友更近且够得着（`mateD + 0.8 < mineD`）→ 本次不触发；双方（玩家、AI 队友、AI 对手）共用同一套判定。
7. **手动优先**：`inp.hit / inp.hitHeld / hitBuffer > 0` 时不走自动；自动同样消耗每队 3 次触球，并受 `hitCd / hitGap / lastHitterByTeam` 限制。
8. **出球方向**：自动起球按 `pass` 处理，高吊到本队二传/进攻区（自家半场），不是直接打回对面；只有第三拍用尽或极端角度才 `send` 过网。

### 11.6 本节遗留风险

- **纯自动口径下普通/困难得分率下降**：`--dig=auto` 让拟人机器人完全不按击球键，而对面两个 AI 都会自动起球，回合触球数被拉长（普通 11.55→14.26、困难 13.28→16.16），玩家得分率 49.3%→40.3%、35.6%→29.5%。真人实战里手动键优先级更高，可以主动干预；这个数字是「只靠自动」的下限，不建议据此直接调难度。
- **简单档胜率 79.2%→70.8%**：分工后队友不再全程贴着玩家补网前，网前双人拦网变少，但换来了后场覆盖更稳。简单档仍是最容易拿分的一档；若需要回到 75%+，建议只调简单档对手的扣球精度，不要取消后场分工。
- **玩家自己触发的自动接球样本少**：拟人机器人站深位、队友按「谁更近」有优先权，玩家自己只有 0.04~0.08 次/场；真人网前漏球后大概率仍是由队友救。`tryAutoDig` 的玩家路径已经由截图 ⑤ 取证（`pid=0 auto pass`），但缺少真人批量样本。
- **自动接球高度带是硬阈值**：球高于 `2.3 / 2.15 / 2.0m` 从头顶飞过时不碰、低于 `0.35m` 的贴地球也不碰，极少数「差一点」的球会漏；这是为了避免前排截胡后场球和地面二次触球，后续若要更宽松，建议只调简单档上限。
- **责任区边界 3.4m 附近可能让球**：落点正好卡在 `|z|≈3.4m` 时，前排按「让给后排队友」处理，若队友同时判定「自己够不着」就会出现短暂无人接；目前靠 `mate + 0.8m` 优先权和 ETA 兜底，没有按实际跑动时间逐帧抢占。
- **上前二传样本占比低（2.9%~6.6%）**：回撤数据是这几十次「上前二传」的平均；连续多回合对手快攻时，队友仍可能刚回撤就被下一拍调用。

## 12. 第五轮：网前「二传」修复 + 拦网容错

本轮只动模拟层（`world.ts` / `ai.ts`）和验证工具（`bench-netset` / `bench-block` / `shot-netset-frames` / `probe-netset`）；联机协议、UI 布局、按钮贴图、对手扣球高度与球速全部未改。

数据口径统一为**拟人机器人**（摇杆抖动 + 间歇冲刺 + 150~300ms 按键延迟），零延迟理想机器人只作为对照列。

### 12.1 现象一：网前「二传」变成直接过网

**根因（两条同时成立）**

1. **二传落点固定在“进攻区坐标”**：旧 `setAim` 无论队友在哪，都把球吊到 `z=±1.75` 的固定进攻点。如果队友刚被 `coverBack` 拉回后场（`|z|≈4.35m`），球就落在无人区 → 队友赶不到，球落地；下一拍轮到玩家时触球已用尽，只能处理过网。看起来就像“按二传 → 球过网”。
2. **第三拍按「二传」没有独立语义**：旧代码直接把 `setupBuffer` 退化成普通击球，`kind` 仍按 `attack/send` 判定，于是球被“打”过网，而不是“吊”给队友。

**新规则（`world.ts`）**

- 二传按钮走 `tryHit(force='setup')`，并在 `setAim()` 里按**队友冲刺路径**算落点：
  - 进攻节点取 `x = 队友 x × 0.92`、`z = 1.9m`（网前进攻点）；
  - 弧顶：队友在深后场（`|z|>3.6m`）用 5.4m，否则 4.9m；
  - 用球的滞空时间算队友可达距离 `reach = 6.2 × flight × 0.95`；赶不上就把落点沿“队友当前位置 → 进攻节点”的连线收短，保证**球落在队友能跑到并起跳的位置**，而不是固定坐标。
- AI 队友收到二传后 `quickAttack` 立刻生效：`touches===1` 且 `isAttacker` 时，按 `ballTimeToHeight(spikeMaxY) ≤ 0.35s` 提前起跳，冲上来直接扣。
- **只有第三拍（`touches>=2`）才允许处理过网**：`force='send'` 高吊过网，并记 `setFallbacks.touchesExhausted`；无队友记 `noMate`；按太早够不着记 `noReach`（事件 `setFallback`）。三种原因都在 `World.setFallbacks` 里累计，方便实机排查。
- 联机双人语义不变：同一个 `World` 里 `attackPlan.attackerId` 指向真人队友时，二传落点按该真人的位置算，AI 不会接管。

- **零延迟理想机器人**同表也是 `100% / 0% / 0%`（该场景里按键延迟不改变触球点，因为二传窗口本身有 0.6s 缓冲），所以这组结论在两种口径下一致，不存在“理想机器人 100%、真人 0%”的偏差。

### 12.4 本节遗留风险

- **真人拦网仍无整场样本**：整场 bench 的拟人机器人不按拦网键（`humanBlockJumps = 0`），表里的“我方拦网”仍由 AI 队友贡献；真人口径只有 `bench-block` 的定点曲线 + 一张实机截图。
- **横向偏差模型是参数化的**：`σ(lead)=0.55+0.9×lead` 没有用真人数据标定，只能说明“越早起跳越依赖预判”的方向；有真人样本后应重算 σ 与截断。
- **二传提前按会浪费一拍**：提前 0.6s 以上（球还没进入 1.75m 触球范围）按「二传」，缓冲会耗尽并记 `noReach`，这一拍不触球；目前没有“按住二传等球”的更长缓冲，实机建议在球接近时再按。
- **打手出界阈值仍按比例**：`|dx| / halfW > 0.8` 判边缘；halfW 加宽后边缘区也随之外移，是“拦网次数上去、得分率略降”的直接原因。若要提高拦网收益，可改为固定 0.62m 的边缘阈值。
- **联机双人只做了语义回归**：协议未变、两真人同队时二传按真人队友位置算落点，但没有双真人实机样本。
