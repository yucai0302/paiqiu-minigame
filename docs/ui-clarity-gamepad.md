# 手柄四键重排 + 画面清晰度优化（改动报告）

测试环境：Chrome + `web/wx-test.html`（wx 垫片），视口 390×844 @ deviceScaleFactor 3（模拟 iPhone 竖屏）。
玩法逻辑、联机协议、启动兜底/watchdog 均未改动。

---

## 1. 结论

**模糊不是一个参数造成的，是三条链路同时欠采样：**

| 链路 | 改动前 | 问题 | 改动后 |
| --- | --- | --- | --- |
| 主画布缓冲 | DPR 被硬钳在 **2** | 780×1688 缓冲被合成器放大 **1.5×** 到 1170×2532 | DPR **3**（按档位/预算取），1170×2532 |
| 全屏 2D 层（首页/HUD/暂停/结算） | 写死 **1.5×**（585×1266） | 显示端放大 **2×**，文字整片发虚 | 跟着 DPR 走 **3×**（1170×2532），且整屏只保留一张 canvas 原地复用 |
| UI 贴图（按钮/记分牌/名牌） | 写死 **2×** | DPR3 上放大 **1.5×** | 启动期按 **3×** 烘焙 |
| 地板烘焙贴图 | 704×1104 | 投影宽约 1170px → 放大约 **1.66×** | 1056×1656（1.5× 倍率）→ 约 1.11× |

量化改善（拉普拉斯方差，越大越锐；裁切自同一近景机位）：

| 区域 | 改前 | 改后 | 提升 |
| --- | --- | --- | --- |
| 记分牌数字/队名 | 209.4 | 255.6 | **+22.1%** |
| 名牌文字 + 号码徽章 | 146.0 | 210.1 | **+43.9%** |
| 球网底座/场地白线 | 96.8 | 121.2 | **+25.2%** |

**按钮：不是等比放大，是重排。**

- 击球主键直径 66 → **74**（+12.1%），跳跃/拦网 52 → **58**（+11.5%），冲刺 46 → **52**（+13.0%）；
- 命中半径独立于视觉：击球 33 → **43**（+30.3%），跳跃/拦网 26 → **33**，冲刺 23 → **30**；
- 重叠：改前 2×2 方格在 DPR/safe 变化下行距被压到 47.3px，主键与跳跃**垂直重叠 11.6px**（刘海屏）；改成对角错落后 **最小视觉净缝 11.0px、最小命中净缝 2.2px**，四键完整落在安全区内；
- **摇杆完全没动**：尺寸 124/64、x=76、绝对位置按原 1/6 手柄带计算。

**代价**：贴图显存 14.5MB → **32.6MB**；主画布颜色缓冲 5.27MB → 11.85MB。软渲染帧时间 66.96ms → 104.41ms（仅同环境相对参考，**不代表真机**）。已配套启动期分档 + 运行时按帧率降档（已验证 3 → 2.5 会触发）。

## 2. 手柄重排

### 2.1 两套方案取舍

| 方案 | 做法 | 拇指可达度 | 遮挡球场 | 结论 |
| --- | --- | --- | --- | --- |
| A 弧形放射 | 以右下角拇指根为圆心画半径 ~140 的弧，五键沿 -25°/-55°/-85°/-115° 排开 | 弧上最外两键需手腕转动才能按到 | 弧线顶到 3D 视口下沿，明显压球场 | 未采用 |
| B 2+2 对角错落（采用） | 内列（冲刺/拦网）左移、外列（跳跃/击球）靠右；上下两排整体错开 42px，底部一行贴安全区 | 击球在最右下的自然落点，其余键按频率递减大小与距离 | 全部落在手柄带内，顶边不越过 3D 视口 | **采用** |

选 B 的原因：竖屏右手拇指的自然落点是右下角，A 方案的弧线把"拦网/冲刺"推到内上方，反而要拇指回勾；B 用横向 42px + 纵向 66px 的对角错位，不加大手柄带高度也能把四个圆分开。

### 2.4 安全区（刘海屏 safeBottom=34）

手柄带高度 `padH = max(146, round(H/6)+5) + min(safeBottom,34)` = **180**（改前 141），
3D 视口下沿 y=664（改前 703）。四键随之下移量 0、整体上移 34：

| 检查项 | 结果 |
| --- | --- |
| 最右视觉边 | 338+37 = 375 → 距右边 15px |
| 最下视觉边 | 767+37 = 804 → 距屏底 40px，距安全区下沿(810) **6px** |
| 最下命中边 | 767+43 = 810 → 与安全区下沿**重合（0px 溢出）** |
| 顶边（跳跃） | 701-29 = 672 → 未越过 3D 视口下沿 664（在带内 8px） |
| 蓄力条 / 播报区 | 均在手柄带之上，与四键无交集 |

> 取舍：为了把四键整条放进安全区，`padH` 比改前多 5px（safe=0）/ 39px（safe=34），3D 视口相应变矮。这是刘海屏上唯一必然的代价，已尽量少取（safe 上限 34）。

### 2.5 视觉与手感

- 贴图跟随 DPR 烘焙（2× → 3×），图标/文字按 `r / 基准半径` 等比放大，大键里图标不再偏小；
- 按压反馈：贴图切深色版 + **缩放 0.86 + 下沉 2px**（改前只有 0.9 缩放）；
- 摇杆尺寸、贴图倍率（2×）、位置、判定（含 `joyOrigin` 跟手偏移）**全部未改**；
- 触控行为未改：四点触控 id 分配、`y0` 上部边界、蓄力瞄准松手发球、两段式主按钮逻辑均原样。

## 5. 降档策略

**启动期分档**（`resolution.ts`，解析一次固定整个会话）：

| 档位 | 判定 | DPR 上限 | 像素预算 | UI/2D 层倍率 | 地板 | 名牌 |
| --- | --- | --- | --- | --- | --- | --- |
| high | benchmarkLevel ≥ 30，或屏幕理论像素 ≥ 2.4M | 3 | 3.0 Mpx | 3× | 1.5× | 1.25× |
| mid | benchmarkLevel ≥ 15，或 ≥ 1.2M | 2.5 | 2.2 Mpx | 2.5× | 1.25× | 1.1× |
| low | 其余（iOS 无 benchmark 时按屏幕规模推断） | 2 | 1.5 Mpx | 2× | 1× | 1× |

最终 `dpr = min(档位上限, 设备 DPR, sqrt(预算/屏幕像素))`，避免大屏机被无脑拉满；2D 贴图倍率跟随 dpr（1x 画布拉到 3x 设备是"糊"的主因）。

**运行期降档**（`app.ts`）：进入对局满 4s 后，连续 3 个统计周期 fps < 45 且不在 8s 冷却内 → DPR 3 → 2.5 → 2，只降不升，贴图不重烘焙。

已实测触发（软渲染 10fps 环境下）：

```
before start: {state:"start", dpr:3,    buffer:"1170x2532"}
t+8s:         {state:"playing", dpr:3,  buffer:"1170x2532"}
t+10s:        {state:"playing", dpr:2.5, buffer:"975x2110"}   ← 降档生效
t+14s:        {state:"playing", dpr:2.5, buffer:"975x2110"}
```

## 7. 遗留风险 / 未完成

1. **真机未验证**：以上数据全部来自浏览器 wx 垫片 + SwiftShader。iOS 真机 `safeArea`、Android `benchmarkLevel` 的实际取值需真机复测。
2. **WebGL1 回退**：地板 1056×1656、名牌 320×140 均为非 2 的幂，且 `generateMipmaps=false`。WebGL2 下无问题；若低端机回退 WebGL1，NPOT 贴图只能用 CLAMP+LINEAR、无 mipmap，远处地板可能出现闪烁/摩尔纹——需真机 WebGL1 路径观察。
3. **显存上界 32.6MB**：高端档贴图显存相比改前翻倍，低端 Android（2GB 内存档）应依赖 mid/low 档自动回落；真实内存占用未在真机测。
4. **软渲染帧时间不可外推**：104ms/132ms 的波动说明该指标只适合同环境相对比较；真机 DPR3 的实际帧时间待测。
5. **3D 视口变矮**：`padH` +5px / +39px，刘海屏上球场主体比改前矮 39px（为保证四键完整进安全区的取舍）。
6. **命中区最小净缝 2.2px**（hit-jump）：命中区互不重叠，但容错边界很窄；若真机上误触频发，可只把击球命中半径从 43 降到 41（视觉不变）。
7. 首页 toast（偶发提示条）仍按 2× 烘焙，属极小概率出现的小贴图，未提升。
